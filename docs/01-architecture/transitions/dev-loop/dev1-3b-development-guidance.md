## 5. Proposed independent-review procedure (audit E.7): described for later approval, NOT adopted

The audit proposed (E.7, "Independence of review without repetition"):

1. **Verify what hashes and TRX already prove**: subtree hashes equal the reviewed commit; TRX totals, rcsi split and timestamps match the record; SQL markers and container start time consistent; build log 0 errors.
2. **Re-run independently on the reviewer's own clean build**: every new or changed test class on both isolation modes; the classes exercising changed production files that the implementer's filter omitted; at least one novel mutation per claimed property; any skipped or not-run item judged material.
3. **Do not repeat** the whole unit, UI and architecture suites or the full focused set when step 1 passes.
4. Review records gain the same provenance and timing block as implementation records.

Status: **proposal only.** Adoption is a change to how independent validation is done. It needs the owner's and the security owner's explicit authorization, at a named package boundary (DEV-1 plan, section 5 DEV-1.3 and section 9 item 5). Until then the three templates keep the current obligations, including the reviewer's own re-run of the focused set. The DEV-1.3A experience is a caution rather than support: each review round found a further way for something outside the Git tree to change what was compiled, and the finding came from re-running and attacking, not from re-reading hashes. Step 3 in particular assumes the hashes and TRX are themselves trustworthy, which is what a first-use toolkit has not yet earned (open condition 1 below).

## 6. Validation tiers and toolkit guidance: adoption status

## 7. `scripts/ci/test.ps1`: defect and repair

**Verified defect.** On the base commit `pwsh scripts/ci/test.ps1 -Filter NoSuchClass` exits 1 with "The term '...\scripts\dev\Get-DevDotNetSdk.ps1' is not recognized". The helper was deleted on 2026-06-18 (audit E.3). `CONTRIBUTING.md` named the script as the supported test command, so every documented invocation failed.

**Repair (minimal, same contract as the sibling `build.ps1`).** The SDK-resolution lines are gone: the script uses `dotnet` from `PATH` (global.json is applied by `dotnet` from the repository root) and stops with a clear message if there is none. Two small additions serve the "never silently select the wrong scope" requirement, and nothing else changed:

- `-Filter` accepts only `[A-Za-z0-9_.]` (a `ValidatePattern` ending in `\z`, not `$`, because `$` in a .NET regex also matches before a final newline), so it cannot carry `|`, `&`, `!`, `=`, `~`, a newline or a second property into `FullyQualifiedName~<fragment>`.
- Each run writes TRX files to a fresh folder `artifacts/test-results/<utc>/`, and after `dotnet test` exits 0 the script requires at least one TRX with at least one test **executed**, no recorded failure, and prints passed, skipped and failed counts. `dotnet test` exits 0 when a filter matches no test (observed in this package: nine TRX files, zero executed), which previously could not be told from success. A non-zero test-host exit is still a thrown failure, so the exit code of the script is non-zero for failing tests, a crashed host, an unreachable prerequisite and a missing SDK.

Not changed: no environment file is read, no credential is touched or printed, `APPERTURE_*`/`MSSQL_*` variables pass through untouched, SQL tests keep failing without SQL (the script has no skip or optional-SQL switch), `.github/workflows/ci.yml` is untouched (CI does not use this script), no redesign of test orchestration. A `-Project` or multi-class filter was considered and left out as scope growth.

## 13. Follow-up after acceptance: the success condition of `test.ps1`

The owner conditionally accepted this package and asked for one targeted correction (residual (a) of section 10), then a PR. The correction is two commits: `d6d1d9f` (first version; reviewed at `b6e5509`) and `545aabd` (the changes the review required, section 14). `scripts/ci/test.ps1` is now `E642AE40...D71E` (the accepted `339c219` version was `4E7444D0...C5E1`; `d6d1d9f` was `2FEFB14D...5D54`).

**The condition that was wrong.** After `dotnet test` exited 0 the script required only "at least one test executed" and "no failed, errored, timed-out or aborted test". A result file with `executed > 0` and `passed = 0`, `failed = 0` (inconclusive, not runnable or disconnected tests, or counters that were silent about them) therefore printed `Tests passed: 0 passed, 0 skipped or not executed, 0 failed`. Related holes in the same block: a missing count was read as 0 (`[int]''`), a negative count was accepted (a file with `failed="-1"` produced `Tests passed: ... -1 failed`), `ResultSummary outcome` was never read, and the individual result records were never compared with the counters.

**The corrected rule (smallest change inside the same block).**

| Situation | Outcome |
|---|---|
| Host exit non-zero; any failed, errored, timed-out or aborted count | Fails, as before |
| No result file, or no test executed | Fails, as before |
| Executed tests that did not pass (`executed != passed`), or a non-zero inconclusive / not-runnable / disconnected / warning / pending / in-progress / passed-but-run-aborted / completed bucket | **Fails (new)**; message "without a passing verdict" |
| Result file unreadable, truncated, zero bytes, no counters, a required count missing or not a whole number (including a negative one), or a run outcome other than `Completed` | **Fails (new for the last four)** |
| Executed != passed **in any one file** (also when another file offsets it, or a file claims more passes than it executed) | **Fails (new)**; judged per file |
| A file's result records are not exactly its passed records plus its skipped (`NotExecuted`) records: a `Failed`, `Error` or other record standing in for a skip or for a pass, a missing skip record, a wrong passed-record count | **Fails (new)**; judged per file and by outcome |
| More than one counters element or more than one run summary in a file | **Fails (new)** |
| Passing tests plus reported skips, mixed in one file or across files | Passes, skips counted and printed ("N skipped or not executed"), never counted as passed |
| A project whose tests were all skipped, next to projects that executed tests | Passes; the assembly is **named** and classed "not authoritative for it" |
| A project that selected no test (`total = 0`) | **Fails an unfiltered run** (a project discovered nothing, so part of the suite never ran); under `-Filter` it is expected and reported ("N result file(s) selected no test") |
| Every selected test skipped, nothing executed | Fails, as before |

*Why that policy for several result files.* One TRX is written per test project. Under `-Filter` all but the project holding the match write `total = 0` (observed: eight of nine). Without `-Filter` every one of the nine test projects discovers tests today (`dotnet test <project> --list-tests`: 6, 7, 38, 146, 1, 2,548, 524, 1,497 and 5,303), so an empty file means a project that did not discover its tests while others hid it in the total. Gated assemblies are the reason an all-skipped file is allowed rather than failed (a local run of `Apperture.BrowserTests` skips tests without its gate); the output says so by name. **The unfiltered-empty rule rests on the nine-project fact above; a future test project that legitimately has no tests would need this rule revisited.** It was not exercised on a full unfiltered solution run (about two hours); it is covered by the controls and by the filtered real runs below.

**Real TRX shapes, observed before the rule was written** (all from this tree): clean, `total=17 executed=17 passed=17`, `Completed`; failing, `outcome=Failed`; all skipped, `total=5 executed=0 notExecuted=0` with five `NotExecuted` records (so skipped is `total - executed`, as the script already computed); mixed, `total=20 executed=19 passed=19` with one `NotExecuted` record.
